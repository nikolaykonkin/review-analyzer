## Как устроено

### Конфигурация

Конфигурация читается из переменных окружения функцией `config.Load` (`internal/config/config.go`); в приложении ей передается `os.Getenv`. Пустая переменная считается незаданной.

| Переменная | По умолчанию | Допустимые значения |
|---|---|---|
| `HTTP_PORT` | `8080` | целое число от 1 до 65535 |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` (регистр не важен) |

При недопустимых значениях сервис не стартует: `Load` собирает все ошибки через `errors.Join` и возвращает их разом, процесс завершается с кодом 1 (`cmd/service/main.go`). Шаблон переменных лежит в `.env.example`. Сам файл `.env` приложение не читает: переменные нужно передать через окружение.

### Логирование

Логи пишутся в stdout в формате JSON через `log/slog` (`internal/logger/logger.go`). Минимальный уровень задается переменной `LOG_LEVEL`.

### Корректная остановка

Сервис перехватывает SIGINT и SIGTERM (`cmd/service/main.go`), перестает принимать новые соединения и ждет завершения текущих запросов не дольше 10 секунд (константа `shutdownTimeout`).

### HTTP API

Реализован один маршрут: `GET /healthz` возвращает 200 и тело `ok` (`internal/httpapi/router.go`). Другие методы этого пути получают 405.

## CI/CD

Workflow `.github/workflows/ci.yml` запускается при push в `main` и для pull request. Проверки: `gofmt -l`, `go vet`, `go build`, `go test`. Сборка Docker-образов и интеграционные тесты пока не подключены.

## Структура проекта

- `cmd/service/main.go` — точка входа сервиса
- `cmd/bot/main.go` — точка входа бота (пока пустой `main`)
- `internal/config/` — загрузка конфигурации из окружения
- `internal/logger/` — конструктор JSON-логгера
- `internal/httpapi/` — HTTP-маршруты сервиса
- `.github/workflows/ci.yml` — проверки в GitHub Actions
- `.env.example` — шаблон переменных окружения
- `.gitattributes` — атрибуты путей для git
- `.gitignore` — исключения git
- `go.mod` — модуль `github.com/nikolaykonkin/review-analyzer`

## Что не реализовано и почему

Проект в разработке, поэтому пока не реализованы: импорт отзывов из CSV, хранение в PostgreSQL, анализ через GigaChat, фоновая обработка, REST API (кроме `/healthz`), Telegram-бот (`cmd/bot/main.go` содержит пустой `main`), метрики, Docker-образы и интеграционные тесты в CI.
